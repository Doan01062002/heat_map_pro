02. TƯ DUY KIẾN TRÚC

Tại sao không dùng 1 ngôn ngữ? — Polyglot Strategy

Go Network Engine + OSRM C++ Container Isolation
❌ Nếu CHỈ dùng C++
  • Ưu điểm: Map-matching siêu tốc, tối ưu bộ nhớ.
  • Nhược điểm: Viết WebSocket, auth, connection pool bằng C++ cực kỳ phức tạp và chậm tiến độ.
  • RỦI RO: 1 lỗi Memory Leak nhỏ có thể làm sập toàn bộ hệ thống!
❌ Nếu CHỈ dùng Golang
  • Ưu điểm: Goroutines xuất sắc, I/O mạng tuyệt vời.
  • Nhược điểm: Go không có sẵn thư viện Map-matching (HMM) chuẩn công nghiệp như C++.
  • RỦI RO: Tự viết lại Map-matching tốn hàng tháng và dễ sai sót.
💡 GIẢI PHÁP TỐI ƯU: Go Ingestion & Concurrency + OSRM C++ trong Docker độc lập

➔ Cô lập lỗi (Fault Isolation): Nếu OSRM gặp trục trặc, Go vẫn nhận GPS bình thường, circuit breaker kích hoạt sau 500ms mà không sập kết nối khách hàng!

04. TẦNG 1: INGESTION

Hứng dữ liệu & Bộ tiền lọc Bounding Box O(1)

Protobuf Binary • Goroutines Concurrency • Spatial Pre-filtering
Protobuf & Quản lý Kết nối Concurrency
  • Protobuf Binary Encoding: Giảm ~80% dung lượng so với JSON truyền thống (< 1KB / batch).
  • Goroutines siêu nhẹ: Quản lý hàng ngàn kết nối song song với bộ nhớ RAM < 40MB.
  • Ranh giới độc lập: Package Ingestion không import Redis hay PostgreSQL.
Cơ chế Lọc Bounding Box O(1) trên RAM
  • Tạo khung bao: Tính toán min/max Lat-Lng + 50m buffer khi xe bắt đầu chuyến.
  • Kiểm tra tức thời (~0.001ms): Chỉ dùng 4 phép so sánh số học trên CPU.
  • Tiết kiệm 70% CPU: 70% điểm trong vùng an toàn bị bỏ qua, không gọi OSRM!
Thuật toán Bounding Box: Giảm tải 70% áp lực cho cụm C++ Map-matching
05. TẦNG 2: MAP MATCHING

Nắn đường & Đo khoảng cách sai lệch (OSRM C++)

Hidden Markov Model (HMM) • Haversine Metric • Circuit Breaker
Open Source Routing Machine (OSRM C++)
  • Engine C++ Docker: Chạy độc lập, chỉ chiếm ~400MB RAM cho toàn bộ bản đồ Việt Nam (MLD).
  • REST Endpoint: Go gọi /match/v1/driving/... với tập tọa độ GPS nghi vấn.
  • Strict Timeout 500ms: Tự động ngắt kết nối nếu OSRM quá tải, bảo vệ toàn hệ thống.
Thuật toán HMM & Haversine Distance
  • Hidden Markov Model (HMM): Khớp tọa độ GPS nhiễu vào tim đường chính xác nhất theo xác suất chuyển trạng thái.
  • Haversine Distance: Tính khoảng cách hình cầu giữa điểm khớp và lộ trình chỉ định.
  • Xác nhận vi phạm: Nếu khoảng cách > 50 mét ➔ Kích hoạt sự kiện Lệch Tuyến.
Thuật toán HMM: Khớp GPS nhiễu vào tim đường và tính khoảng cách Haversine
06. TẦNG 3: REAL-TIME BROADCAST

Uber H3 Indexing & Lock-Free Aggregator

Resolution 8 Hexagons • sync.Map + Atomic • Redis Pub/Sub
Uber H3 Spatial Index (Resolution 8)
  • Độ phân giải Res 8 (~460m): Diện tích 0.74 km² — Tối ưu nhất cho quy mô khu phố đô thị Việt Nam.
  • Tính toán O(1) trên CPU: Chuyển (Lat, Lng) ➔ H3 Cell Hash dạng String tức thì, không cần tra cứu GIS.
  • Nén 98% dữ liệu: Rút gọn từ 500KB GPS raw xuống chỉ còn 10KB bản tin H3 tổng hợp.
Lock-Free Concurrency & Redis Pub/Sub
  • sync.Map + atomic.AddUint64: Hàng ngàn luồng đếm trên RAM mà không cần khóa Mutex.
  • Snapshot 1 giây: atomic.SwapUint64 lấy dữ liệu và reset bộ đếm trong 1 chu kỳ CPU.
  • Zero Database I/O: Luồng phát nóng hoàn toàn không chạm vào ổ cứng Database!
Uber H3 Res 8: Lục giác đều đồng nhất, tính toán O(1) không méo góc

10. BỘ GIẢ LẬP ĐA LUỒNG

Multi-threaded Driver Simulator (Web Workers)

Web Workers Threads • GPS Jitter & Noise • Deviation Injection
Kiến trúc Đa luồng Web Workers
  • Không block UI: 4 Web Worker threads chạy nền, tính toán tọa độ cho 500+ xe mà trình duyệt vẫn mượt 60 FPS.
  • Dữ liệu bản đồ thực tế: Xe di chuyển theo các tuyến đường thực tại TP.HCM.
  • Protobuf Streaming: Tự động encode nhị phân và gửi qua WebSocket.
Kịch bản Kiểm thử Chủ động (Testing)
  • Deviation Injection: Bơm các kịch bản tài xế đi đường vòng, lạc đường có chủ đích.
  • GPS Noise & Jitter: Giả lập sai số định vị GPS vệ tinh 5-15m và trễ mạng 4G thực tế.
  • Stress Test: Kiểm thử sức chịu tải và độ ổn định của cụm server.
